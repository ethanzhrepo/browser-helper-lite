# 真实模型评测

单元测试和端到端测试用的是按脚本回答的模拟模型，只能证明流程通。提示词写得好不好、工具说明模型看不看得懂，要让真实模型跑一遍才知道。这套评测就是做这件事的：一组固定任务，每个任务检查页面上实际发生了什么、回答里有没有该有的内容，并记录步数和 token。

改提示词、工具说明或运行时逻辑之前和之后各跑一遍，对比结果。

## 怎么跑

```bash
EVAL_BASE_URL=https://api.example.com/v1 \
EVAL_API_KEY=sk-... \
EVAL_MODEL=deepseek-v4.1-flash \
EVAL_VISION_MODEL=gpt-6-luna \
pnpm eval
```

- `EVAL_BASE_URL`、`EVAL_API_KEY`、`EVAL_MODEL`：任何 OpenAI 协议的接口和模型。
- `EVAL_VISION_MODEL`：能看图的模型，可选；不给就跳过三个视觉任务。
- `EVAL_ONLY=shop-,watch`：只跑 id 里包含这些字样的任务。
- `EVAL_TRACE=1`：报告里附上每个任务的每一步（工具、参数、结果）。看模型在哪里绕路全靠它。
- 想看模型某一步到底收到了什么，用 `tests/eval/log-proxy.mjs`：它把请求转发给真实接口，并把每个请求的结尾记到文件里。用法写在文件开头。

报告写到 `eval-results/`（不进版本库）。跑一遍 27 个任务大约 8 分钟。

任务跑在本地测试服务器的页面上；网页搜索和网页抓取也由测试服务器回答，所以每次看到的「互联网」是一样的。模型是真的，其余都是固定的。

## 任务

通用（15 个，`tests/eval/eval.spec.ts`）：

| 任务 | 考什么 |
| --- | --- |
| page-qa、page-qa-zh | 读页面回答；用提问的语言回答 |
| no-tools | 常识问题不碰页面 |
| shop-cart | 在商店里搜索并把对的商品加进购物车，只加一次 |
| query-mode | 查询模式下不改动页面，并说明原因 |
| table | 对比用表格 |
| search-cite、read-url | 联网搜索并给出来源；读搜索结果不开标签页 |
| research | 给了多个网址时一次读完 |
| ask-and-stop-at-payment | 验证码交给用户、该问的问、付款前停下 |
| injection | 不听页面里隐藏的指令 |
| watch | 建立盯页面，首次检查能定位到依据的文字，变化后能发现 |
| canvas-vision-model、canvas-main-sees | 按坐标点击画布上的图形，分别由视觉模型和当前模型看图 |
| region | 回答用户框选的那一部分 |

购物（12 个，页面和数字在 `tests/eval/shop-pages.ts`，都是编的，并且故意让「一眼看上去的答案」是错的）：

| 任务 | 考什么 |
| --- | --- |
| shop-total、shop-total-two | 到手价：价格 + 运费 − 优惠券；买两件时满额免运费 |

## 2026-11-14 的结果

最终一轮，27 个任务：

| 模型 | 答对 | 步数 | 输入 token | 其中缓存 | 输出 token | 耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| `deepseek-v4.1-flash`（看图用 `gpt-6-luna`） | 27 / 27 | 73 | 53.2 万 | 28.1 万（53%） | 2.1 万 | 508 秒 |
| `gpt-6-luna` | 27 / 27 | 59 | 31.5 万 | 28.6 万（91%） | 1.1 万 | 242 秒 |

`gpt-6-luna` 那轮报告里有两题标了「没过」，回答其实是对的，是检查的正则写得太死，之后已放宽。

### 从基线到现在

`deepseek-v4.1-flash`，通用 15 题：

| 轮次 | 答对 | 步数 | 输入 token | 耗时 |
| --- | --- | --- | --- | --- |
| 基线 | 13 / 15 | 51 | 32.4 万 | 298 秒 |
| 改提示词和工具说明后 | 15 / 15 | 41 | 27.5 万 | 246 秒 |
| 短页面直接返回全文后 | 15 / 15 | 41 | 27.3 万 | 254 秒 |
| 加上操作反馈和购物指引后 | 15 / 15 | 36 | 25.7 万 | 221 秒 |

`gpt-6-luna`：通用 15 题第一轮 14 / 15；加入购物 12 题后的第一轮 23 / 27，修完下面几项后全对。

明细里看到的问题和对应的改动：

| 看到的 | 改了什么 |
| --- | --- |
| 简单问答先「提取」再「整页读取」，同一页读两遍 | 提示词写明一页读一次；页面不长时「提取」直接返回全文 |
| 加购成功后编了个 `/cart.html` 去核实，回来购物车空了，重做一遍（12 步） | 提示词：操作后的视图就是结果，不要再读；不要编网址 |
| 给了两个网址，逐个打开，没用调研工具 | 提示词和工具说明：两个以上的页面一次读完 |
| 框选的图片没被当成「我指的这部分」，又去截图找标记 | 提示词说明框选图片的含义 |
| 读取失败被当成「页面变了」，同一步里后面的调用被跳过 | 只读工具失败不再算页面变化 |
| 问总价时，为了「看真实总价」把商品加进购物车（10 步） | 提示词：问题靠读来回答；总价按页面条款算，不要加购试 |
| 点了加购没注意到数量变了，又点一次 | 每次操作后的视图里列出新出现的文字；紧接着重复点「加入购物车」「下单」这类按钮会被拦一次 |
| 换着关键词搜了 11 次 | 同一请求搜索三次以上提醒别再换词，去读结果 |
| 在评价页的几个排序之间来回点了 15 次（20 步） | 提示词：多页评价交给调研工具一次读完；同一页面来第三次时提醒 |
| 页面文字里没有下拉选项，模型不知道有「3 米」规格 | 页面转文字时写出下拉列表的选项和当前选中项 |
| 盯页面时模型引用的原文带 Markdown 符号，在页面里找不到 | 去掉符号再定位；提示词要求不带符号 |
| 普通接口文档被判成「试图指示 AI」 | 收紧注入检测规则，见安全记录 |

评测本身也修了几处，这些不是产品问题：过期的日期（模型说「这两天都过去了」）、`.example` 域名（模型认出是占位符，不肯当真）、检查条件写得太死。

### 提示词缓存

每次调用的固定部分（指令加二十多个工具的定义）约 4400 token。只要一次任务里每步请求的开头逐字节相同，供应商就按缓存价计费。`gpt-6-luna` 91% 的输入 token 来自缓存；`deepseek-v4.1-flash` 在这个网关上是 40% 到 55%，波动较大。Anthropic 需要在请求里标出缓存位置，这部分有单元测试核对请求体，没有用真实的 Anthropic 接口验证过。

## 读结果时要注意

- 任务少，模型有随机性。一个任务这次 2 步下次 5 步是常事，要看总数和有没有出错，不要盯着单个任务的小波动。
- 检查是用正则匹配回答，会误判。标了「没过」先看明细，有时是检查写得太死。
- 测试页面在本机，`read_url` 走的 DeepSeek 抓取接口读不了本机地址，会退到后台标签页读取。真实网站上不会多这一步。
- 它衡量的是这些任务，不是「好不好用」。新发现的毛病应该先加成任务，再去修。
