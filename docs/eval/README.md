# 真实模型评测

单元测试和端到端测试用的是按脚本回答的模拟模型，只能证明流程通。提示词写得好不好、工具说明模型看不看得懂，要让真实模型跑一遍才知道。这套评测就是做这件事的：一组固定任务，每个任务检查页面上实际发生了什么、回答里有没有该有的内容，并记录步数和 token。

改提示词、工具说明或运行时逻辑之前和之后各跑一遍，对比结果。

## 怎么跑

```bash
EVAL_BASE_URL=https://api.example.com/v1 \
EVAL_API_KEY=sk-... \
EVAL_MODEL=deepseek-v4.1-flash \
EVAL_VISION_MODEL=gpt-6-luna \
pnpm eval
```

- `EVAL_BASE_URL`、`EVAL_API_KEY`、`EVAL_MODEL`：任何 OpenAI 协议的接口和模型。
- `EVAL_VISION_MODEL`：能看图的模型，可选；不给就跳过三个视觉任务。
- `EVAL_ONLY=shop-,watch`：只跑 id 里包含这些字样的任务。
- `EVAL_TRACE=1`：报告里附上每个任务的每一步（工具、参数、结果）。看模型在哪里绕路全靠它。
- 想看模型某一步到底收到了什么，用 `tests/eval/log-proxy.mjs`：它把请求转发给真实接口，并把每个请求的结尾记到文件里。用法写在文件开头。

报告写到 `eval-results/`（不进版本库）。跑一遍 46 个任务，`deepseek-v4.1-flash` 大约 20 分钟。

任务跑在本地测试服务器的页面上；网页搜索和网页抓取也由测试服务器回答，所以每次看到的「互联网」是一样的。模型是真的，其余都是固定的。

## 2026-11-14 的结果

最终一轮，27 个任务：

| 模型 | 答对 | 步数 | 输入 token | 其中缓存 | 输出 token | 耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| `deepseek-v4.1-flash`（看图用 `gpt-6-luna`） | 27 / 27 | 73 | 53.2 万 | 28.1 万（53%） | 2.1 万 | 508 秒 |
| `gpt-6-luna` | 27 / 27 | 59 | 31.5 万 | 28.6 万（91%） | 1.1 万 | 242 秒 |

`gpt-6-luna` 那轮报告里有两题标了「没过」，回答其实是对的，是检查的正则写得太死，之后已放宽。

### 技能化之后（2026-11-15）

购物指引从系统提示词移到了内置技能里，另加 6 个技能任务，共 33 个：

| 模型 | 答对 | 步数 | 输入 token | 其中缓存 | 输出 token | 耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| `deepseek-v4.1-flash`（看图用 `gpt-6-luna`） | 33 / 33 | 104 | 84.7 万 | 41.7 万（49%） | 3.4 万 | 766 秒 |
| `gpt-6-luna` | 32 / 33 | 86 | 48.9 万 | 43.5 万（89%） | 1.7 万 | 379 秒 |

只看原有的 27 个任务，和技能化之前比：

| 模型 | 之前 | 之后 |
| --- | --- | --- |
| `deepseek-v4.1-flash` | 27 / 27，73 步，53.2 万 | 27 / 27，70 步，54.6 万 |
| `gpt-6-luna` | 27 / 27，59 步，31.5 万 | 26 / 27，64 步，35.9 万 |

`gpt-6-luna` 没过的是 shop-compare：这一次它漏掉了最便宜的那家店。同一题随后单独重复 4 次，4 次都对；技能化之前它在这题上也错过一次。算作波动，但说明这题对它不是稳的。它的输入 token 多了约 14%，多出来的是加载技能的那一步和技能正文。

这一轮看到并处理的：

| 看到的 | 改了什么 |
| --- | --- |
| 问「到手多少钱、要注意什么」，模型加载了比价技能，跑去别的店比价、开论坛（9 步，8 万 token） | 比价技能的描述写明「不用于算当前页面的价格」；提示词：按用户问的加载技能，不按他可能还想要的 |
| 比价时模型先打开商品图、再截图「检查」它，然后决定不展示 | 展示说明里写明图片地址原样使用，不要先打开或查看 |
| 页面文字里其实一直没有下拉列表的选项：正文提取会去掉表单控件，之前写的规则没生效 | 提取前把选项写成文字，带上当前选中项；加了端到端测试 |
| 有了选项之后，模型把当前选中规格的价格当成了用户问的那个规格的价格 | 这句提示原来在购物指引里，随它移进了技能；补回核心提示词：页面显示的是选中项的内容，问别的规格就去选 |
| 评测的检查误判了三次：把「更便宜的那个不满足条件」当成选错；按换行拆分回答；把写成链接的来源当成没给来源 | 放宽检查 |

技能改用 Agent Skills 标准格式之后（内置技能拆成各自的 `SKILL.md`，描述改成先说做什么、再说什么时候用），`deepseek-v4.1-flash` 重跑购物和技能的 19 个任务：19 / 19，69 步，59.1 万输入 token。skill-reputation 这次搜了 8 次（之前 5 次），属于波动范围，但它是最费 token 的一题。

内置技能增加到 18 个之后（2026-11-15），`deepseek-v4.1-flash` 跑全部 46 个任务：45 / 46，170 步，157.9 万输入 token（107.7 万来自缓存，68%），1150 秒。

- 原有 27 个任务：26 / 27，68 步，63.7 万输入 token（之前 54.6 万）。多出来的主要是每次请求里 18 个技能的名称和描述（约 1100 token），其中大部分走缓存。没过的是 ask-and-stop-at-payment：这一次模型没问哪一天，自己选了周六。同一题随后重复 5 次全对，算作波动。
- 技能 19 个任务：19 / 19，102 步，94.3 万输入 token。最费的是导购选型（约 12 万）。

这一轮看到并处理的：

| 看到的 | 改了什么 |
| --- | --- |
| 往 `type="email"` 的输入框打字报错（这类输入框不支持设置光标位置），模型只能逐个字符按键 | 产品缺陷，已修；加了端到端测试，覆盖邮箱和数字输入框 |
| 问「这几个航班哪个带行李最便宜」时模型不加载出行技能，两步直接算对 | 符合「页面能回答的问题不需要技能」；题目改成从别的页面发起的找机票任务 |
| 评测的测试服务器对编造域名的抓取返回了无关页面，模型在票价页之间来回跳了 10 次；退订页面的表单带查询参数导致 404；模拟用户对「缺电话」的提问回答了「发送吧」 | 都是评测环境的问题，已改 |

修绕路之后（2026-11-15，步数上限默认值同时从 30 提到 100），`deepseek-v4.1-flash` 把受影响的四题各跑两轮，八次全对：

| 任务 | 之前 | 之后 |
| --- | --- | --- |
| skill-cancel-subscription | 20 步，16.5 万 token：取消成功后回账户页「核实」，见状态仍是有效，把流程重走了一遍 | 8–9 步，6.4–7.1 万 |
| skill-github-thread | 8 步，6.8 万：页面写 14 条评论只显示 4 条，去找「隐藏评论」，还开了新标签页 | 1–2 步，1.3–2.0 万 |
| skill-reputation | 搜 5–8 次 | 搜 3–4 次，4–6 步 |
| skill-buying-guide | 搜 5 次 | 搜 2–3 次；步数 6–10，仍有波动 |

改了三处技能写法（退订只走一遍流程、以最后一步之后的页面为凭证；GitHub 讨论只总结页面上显示的；口碑和导购先搜两次、读完再决定是否补搜），评测检查里加了步数和搜索次数的上限。运行时另加两道保险：同一地址在一次请求里最多打开 4 次；同一操作以同样方式失败 2 次后不再重试。

分阶段输出之后（2026-11-15），`deepseek-v4.1-flash` 跑购物和技能的 32 个任务：32 个里 31 个标为对，148 步，148.7 万输入 token（93.4 万来自缓存），745 秒。

- 七个分阶段的技能都中途给出了阶段结果（导购 3 次，口碑 2 次，其余 1 到 2 次），多数和下一阶段的第一批工具调用放在同一步里。
- 没过的是退订：新加的检查按「挽留页被打开的次数」判断流程有没有重走，而模型只是点了两下又后退了一次，取消只做了一次。检查改成数「到达最后确认页的次数」，随后两轮都对。
- 代价：同样这 32 题比分阶段之前多用约两成 token。比价从 3–4 步、2.5–3.4 万涨到 6 步、6.4 万；导购 9–12 步、12–17 万。每个阶段多写一段内容，上下文也随之变长。
- 评测环境收紧：评测浏览器里除了模型接口，所有域名都解析到本机。之前有一轮里模型从测试浏览器打开了真实的京东搜索页。
- search-cite 在后续的小范围重跑里错过一次：模型认出搜索结果是本机地址和 `.example` 占位域名，不肯当成来源。是评测素材的老问题。

没有验证的：技能任务只在这两个模型上跑过；论坛页面是本机的假页面，只能说明规则生效（在标签页里打开、不点赞），不能说明真实社交网站读得到。

### 从基线到现在

`deepseek-v4.1-flash`，通用 15 题：

| 轮次 | 答对 | 步数 | 输入 token | 耗时 |
| --- | --- | --- | --- | --- |
| 基线 | 13 / 15 | 51 | 32.4 万 | 298 秒 |
| 改提示词和工具说明后 | 15 / 15 | 41 | 27.5 万 | 246 秒 |
| 短页面直接返回全文后 | 15 / 15 | 41 | 27.3 万 | 254 秒 |
| 加上操作反馈和购物指引后 | 15 / 15 | 36 | 25.7 万 | 221 秒 |

`gpt-6-luna`：通用 15 题第一轮 14 / 15；加入购物 12 题后的第一轮 23 / 27，修完下面几项后全对。

明细里看到的问题和对应的改动：

| 看到的 | 改了什么 |
| --- | --- |
| 简单问答先「提取」再「整页读取」，同一页读两遍 | 提示词写明一页读一次；页面不长时「提取」直接返回全文 |
| 加购成功后编了个 `/cart.html` 去核实，回来购物车空了，重做一遍（12 步） | 提示词：操作后的视图就是结果，不要再读；不要编网址 |
| 给了两个网址，逐个打开，没用调研工具 | 提示词和工具说明：两个以上的页面一次读完 |
| 框选的图片没被当成「我指的这部分」，又去截图找标记 | 提示词说明框选图片的含义 |
| 读取失败被当成「页面变了」，同一步里后面的调用被跳过 | 只读工具失败不再算页面变化 |
| 问总价时，为了「看真实总价」把商品加进购物车（10 步） | 提示词：问题靠读来回答；总价按页面条款算，不要加购试 |
| 点了加购没注意到数量变了，又点一次 | 每次操作后的视图里列出新出现的文字；紧接着重复点「加入购物车」「下单」这类按钮会被拦一次 |
| 换着关键词搜了 11 次 | 同一请求搜索三次以上提醒别再换词，去读结果 |
| 在评价页的几个排序之间来回点了 15 次（20 步） | 提示词：多页评价交给调研工具一次读完；同一页面来第三次时提醒 |
| 页面文字里没有下拉选项，模型不知道有「3 米」规格 | 页面转文字时写出下拉列表的选项和当前选中项 |
| 盯页面时模型引用的原文带 Markdown 符号，在页面里找不到 | 去掉符号再定位；提示词要求不带符号 |
| 普通接口文档被判成「试图指示 AI」 | 收紧注入检测规则，见安全记录 |

评测本身也修了几处，这些不是产品问题：过期的日期（模型说「这两天都过去了」）、`.example` 域名（模型认出是占位符，不肯当真）、检查条件写得太死。

### 提示词缓存

每次调用的固定部分（指令加二十多个工具的定义）约 4400 token。只要一次任务里每步请求的开头逐字节相同，供应商就按缓存价计费。`gpt-6-luna` 91% 的输入 token 来自缓存；`deepseek-v4.1-flash` 在这个网关上是 40% 到 55%，波动较大。Anthropic 需要在请求里标出缓存位置，这部分有单元测试核对请求体，没有用真实的 Anthropic 接口验证过。

## 读结果时要注意

- 任务少，模型有随机性。一个任务这次 2 步下次 5 步是常事，要看总数和有没有出错，不要盯着单个任务的小波动。
- 检查是用正则匹配回答，会误判。标了「没过」先看明细，有时是检查写得太死。
- 测试页面在本机，`read_url` 走的 DeepSeek 抓取接口读不了本机地址，会退到后台标签页读取。真实网站上不会多这一步。
- 它衡量的是这些任务，不是「好不好用」。新发现的毛病应该先加成任务，再去修。
