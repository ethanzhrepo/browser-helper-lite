| # | 严重度 | 问题 | 处理 |

| R1 | 中 | 没有授权的网站上，`press` 仍能通过调试接口按键。读不到焦点元素时错误被吞掉，没有目标的回车算 L1，而调试接口的输入不受 Chrome 网站权限限制。复现：正式构建、授权列表为空、自动模式，回车提交了按钮写着「Delete account」的表单，没有任何确认 | 浏览器控制层在每次读页面、注入脚本、发送输入、截图之前都检查：不是浏览器内部页面、没有被屏蔽、已有网站权限，否则拒绝（`src/agent/browser-controller.ts` 的 `assertAllowed`）。`press`、`scroll` 和所有元素操作先走和读页面一样的权限检查，需要时请求授权；同一次任务里被拒绝的网站不再重复询问。读不到焦点元素时不按键 |

## 新增功能带来的检查点

- **导入备份**：文件用 zod 校验。连接的地址和现有的不一致时，不保留已存的 Key，防止伪造的备份文件把 Key 引到别的服务器。
- **导出**：默认不含 API Key，需要手动打开。（之后改为加密导出，见下文「之后新增：加密导出」。）
- **确认卡片的键盘操作**：Esc 拒绝；回车允许一次，高风险步骤要 ⌘/Ctrl + 回车。正在输入文字、或焦点在按钮上时不响应。卡片出现后的 0.5 秒内仍然不接受允许。
- **右键菜单**：新增 `contextMenus` 权限（没有安装提示）。选中的文字和页面内容和从侧边栏附带时一样，按不可信数据处理。
- **更新检查**：只读取版本号和本项目的发布页地址，其他地址一律忽略。

## 之后新增：截图和按坐标点击

评审修复之后加的功能，记在这里是因为它扩大了助手能碰到的范围。

| 方面 | 做法 |
| --- | --- |
| 谁看截图 | 设置里选：自动（当前模型能看图就用它，否则用视觉模型）、当前模型、视觉模型。「能不能看图」按模型名猜；模型拒收图片时，本次任务改用视觉模型的文字描述 |
| 自动截图 | 只在页面文字不够时：canvas 或视频占视口 20% 以上、别的网站的框架占 20% 以上、多个没有文字的按钮、图片为主而文字很少、连续两步失败。登录页、有密码或验证码输入框的页面、敏感页面名单里的页面不自动截图。可以关闭 |
| 不打扰 | 自动截图不切换标签页，也不会为了截图去挂调试接口；标签页不可见且调试接口没在用时就不截 |
| 按坐标点击（`click_at`） | 坐标取自最新一张截图。页面滚动、缩放或换了网址后坐标作废，必须重新看。落点是可读元素时，和按编号点击一样判断风险；落在 canvas、视频上时，任何模式都要确认，确认卡上有落点周围的截图，不提供「总是允许此网站」；落在别的网站的框架里是 L3。按下前再检查一次落点没有变 |
| 截图对齐 | 截图按宽度等比缩放到 CSS 像素（最长边 1280），不做拉伸；端到端测试核对了预览图的圆圈中心落在目标上 |

剩余风险：

- 当前模型直接看图时，图里的文字没法像页面文字那样用规则检查注入，只靠提示词里「截图是数据」的约束和后面的确认。
- 截图里的卡号、密钥过滤不掉（原来就有，自动截图让它更常发生，所以避开了上面几类页面）。
- 没有用真实的多模态模型测过坐标的准确度，只用模拟模型测了流程。

## 之后新增：加密导出

| 方面 | 做法 |
| --- | --- |
| 加密 | 默认开启。整份备份（设置、对话、Key）用 AES-256-GCM 加密，密钥由密码经 PBKDF2-HMAC-SHA-256 派生（60 万次，随机 16 字节盐，随机 12 字节 IV）。文件里只有应用名、版本、导出时间和加密参数是明文 |
| 密码 | 至少 8 位，输两次；不保存，导出后从表单清掉。比较前做 NFKC 归一，换输入法或系统后同一个密码仍然能用 |
| API Key | 只写进加密的文件。关掉加密时「包含 API Key」不可选，代码里也拒绝把 Key 写进明文（`serializeBackup`）。旧版本导出的明文文件仍然可以导入 |
| 导入 | 加密文件先问密码。密码不对和文件被改动过在 AES-GCM 下无法区分，提示同一句话，什么都不写入。解密后的内容和明文备份走同一套校验和「地址变了就不保留 Key」的规则 |
| 伪造的文件 | 迭代次数限制在 10 万到 1000 万之间：太小等于没有保护，太大会卡住页面 |

剩余风险：

- 密码弱，文件就弱。8 位的下限挡不住拿到文件后的离线猜测，60 万次迭代只是让每次尝试变慢。
- 导出文件没有压缩，对话多时文件较大（Base64 再多三分之一）。

## 之后新增：DeepSeek 搜索的原始问题

DeepSeek 搜索接口可以附带用户的原始问题（`ori_question`）来理解搜索意图。它会把用户消息的前 128 个字发给搜索服务，而提示词本来要求模型不要把个人信息写进搜索词，所以这一项默认关闭，在「设置 › 搜索」里由用户打开；消息里有密钥、令牌或卡号时不发。搜索结果的摘要从 400 字放宽到 1200 字，进入模型的网页文字变多，仍然按不可信数据包裹并检查注入。

## 之后新增：用 DeepSeek 读网页（`read_url`）和 DeepSeek 自带搜索

| 方面 | 做法 |
| --- | --- |
| 什么时候有 | 搜索方式选了 DeepSeek 且「用 DeepSeek 读取网页」开着（默认开）时，模型多一个 `read_url` 工具；关掉后工具不出现，运行时也拒绝 |
| 读到的是什么 | DeepSeek 在它的服务器上抓取，看到的是任何人都能看到的内容，不带用户的登录状态。返回的 Markdown 和页面文字一样按不可信数据包裹并检查注入，最多 4 万字 |
| 网址出去之前 | 和打开网址走同一套检查：被屏蔽的网站拒绝；网址里带数据（邮箱、卡号、长编码）要确认；出现过注入后去新网站要确认；任务里没出现过的网站要确认。另外，带用户名密码、密钥或令牌的网址，以及本机地址，一律不发 |
| 失败 | 404、403 时告诉模型改用标签页打开，不重试 |
| 自带搜索 | 「模型自带搜索」现在支持 DeepSeek：向 `/chat/completions` 声明 `deepseek_web_search`，固定用 `deepseek-flash`、关闭思考（开着思考会变成多步的深度搜索）。回答和来源整体按不可信数据处理，来源里的网址不算「已知网站」 |

剩余风险：

- `read_url` 让网址多经过一个第三方。上面的检查挡的是把数据夹在网址里带出去，挡不住 DeepSeek 一侧对网址的记录。
- 读公开网页不再需要逐站授权（原来要开标签页，需要该网站的访问权限）。被屏蔽的网站仍然不读。

## 之后新增：盯页面、框选提问、回放、存为指令、多页调研

这一批功能里，「盯页面」让助手第一次在用户不看的时候自己运行，其余几个新增了存储和发给模型的内容。

| 功能 | 边界 |
| --- | --- |
| 盯页面（`watch_page`） | **只读**：在后台标签页里打开页面读取文字，不点击、不输入、不滚动。没有该网站权限时，开着 DeepSeek 读网页的话走 Fetch 接口，否则检查失败。**创建要确认**：任何模式下都弹确认卡，写明条件，间隔由用户在卡上选（默认 5 分钟，1 秒到 1 天），只有「允许一次」和「拒绝」。网址还要先过和「打开网址」相同的检查。**少问模型**：第一次判断时让模型指出答案依据的页面原文，扩展在页面里定位到对应元素；之后只比对这些元素的文字，没变就不问模型，变了、找不到了、或距上次判断超过 30 分钟（慢的间隔按 10 倍间隔，最多 6 小时）才重新问。模型没指出可定位的文字时，比对整页文字的摘要。**短间隔**：间隔短于 1 分钟的，页面留在一个收起的标签组里，由注入页面的只读脚本监听 DOM 变化并按间隔比对，有变化才通知后台；后台只认这一项自己的标签页发来的消息，并且自己重新读页面，不采信消息里的内容。页面最快每 30 秒重新加载一次（Chrome 定时器的下限，也避免被网站当成机器人）。用户关掉这个标签页即暂停。**急速**：用户可以在列表里对某一项开启 10 分钟的急速，期间每 5 秒重新加载一次，开启前提示可能触发验证码；只有用户能开，模型不能。到时间自动恢复。**放慢**：页面出现验证码或加载失败时，这一次不读也不问模型，急速立即结束，下一次检查推迟 5 分钟（再失败则 10 分钟），并通知用户；用户点「立即检查」不受推迟限制。**有限度**：最多 20 项，30 天后自动结束，连续 3 次检查失败就停并通知。**通知**：文字是固定措辞加上用户确认过的条件，页面和模型写的内容不进系统通知；点通知只打开这一项自己的网址 |
| 框选提问 | 用户自己拖框选区域。选框在页面里的封闭 shadow root 中，截图前已移除。截图优先用 Chrome 的可见标签页截图；没有全部网站权限时，改用右键菜单（点击即获得该标签页的临时权限）或调试接口截一张后立即断开。图片随消息存储，只在当次请求发给模型，之后的轮次只告诉模型「这里有过一张图」 |
| 回放 | 每个会操作页面的步骤开始前存一张 640 像素宽的截图，结束时再存一张；只在不需要额外打扰时截（标签页正在显示，或调试接口已经在用）。登录页、有密码或验证码输入框的页面、敏感页面名单里的页面不截。截图单独存表，随对话删除而清除，可在「设置 › Agent」里关闭 |
| 存为指令 | 存的是用户的原始请求和上次成功步骤的提纲（工具名加目标文字）。输入的内容里像密钥或卡号的不存。重跑时提纲按不可信数据包裹后交给模型，只当提示用，每一步仍然重新判断风险、该确认的照样确认。**不会自己定时运行**：只有用户输入名字才跑 |
| 多页调研（`research_pages`） | 一次最多 12 个网址。只读任务里已经出现过的网站；没出现过的、网址里带数据的、被屏蔽的一律跳过并告诉模型原因，不在批量里弹确认。每页交给快速模型摘出和问题有关的内容，结果按不可信数据包裹 |
| 表格导出 | CSV 里以 `=`、`+`、`-`、`@` 开头且不是纯数字的单元格前面加单引号，防止表格软件把它当公式执行 |
| 朗读 | 用浏览器的语音合成，文字不发往任何地方 |

剩余风险：

- 页面里的注入文字可能让快速模型误判成「满足」，或者让它指出一段不会变化的文字、从而漏掉真正的变化；前者的后果是一条误报的通知，后者靠定期重新判断兜底。都不会触发任何操作。
- 间隔是「最快」而不是保证：Chrome 会给后台标签页的定时器降频（先是每秒一次，隐藏几分钟后可降到每分钟一次），页面自己靠定时器刷新的内容也一样被降频。不会自己更新的页面只能靠重新加载发现变化，平时最快 30 秒，急速时 5 秒。
- 短间隔的盯页面会让一个标签页长期开着并每 30 秒重新加载，对网站来说是持续的访问。急速期间访问更密，网站可能弹验证码、限流或标记账号；验证码检测靠常见的几种特征，认不出的拦截页会被当成普通页面交给模型判断。
- 急速期间后台靠连续的调用保持运行；Chrome 若中途回收后台，最迟 30 秒后由定时器接上，期间会少刷几次。
- 慢间隔的检查，后台标签页会在标签栏里闪现几秒。
- 盯着的页面不包含在导出文件里：导入一个文件不应该悄悄带来后台任务。
- 回放截图里可能有页面上的个人信息。它们只存在本机，随对话一起删除，也会进入加密或明文的导出文件。
- 存为指令之后「定时自动重跑」没有做，是否要做尚未决定：那会让助手在没人看的时候操作网站，需要先定好边界。

## 之后新增：提示词缓存、购物、注入检测收紧

| 方面 | 做法 |
| --- | --- |
| 提示词缓存 | 不改变发给模型的内容，只是让每次调用的开头（指令、工具、此前的对话）逐字节重复，供应商因此少收费。Anthropic 需要在请求里标出缓存位置，标在指令末尾和「最新一次页面视图之前」；OpenAI 额外带上对话 id 作为缓存路由键；其他供应商自动缓存。为了让历史消息每次渲染一致，用户消息会记下发送时所在标签页的标题和网址 |
| 商品元数据 | 页面的 schema.org 商品数据（名称、价格、库存、卖家、评分）放在页面文字前面。它是页面里人看不到的内容，所以只取有类型的字段、限制长度、价格必须是数字，并且和页面文字一起按不可信数据包裹和检查 |
| 商品页识别 | 侧边栏打开且有该网站权限时，注入一小段只读脚本判断页面是否声明了商品数据，只返回是或否，用来决定显示哪组快捷入口 |
| 注入检测 | 规则从「提到 AI 相关词」收紧为「像是在对 AI 下指令」：要有对象、要丢弃的东西或要发往的地方。25 个普通网页（接口文档、百科、新闻、商店）的误报从 5 个降到 1 个，剩下的是维基「提示词注入」词条里原样引用的攻击语句。原有的攻击样例仍全部命中，并新增了一批 |
| 操作反馈 | 每次操作后的页面视图里，明确列出新出现的文字；连续两次相同操作会提醒；同一请求里搜索三次以上会提醒别再换词重搜。目的是少做重复操作，比如把同一件商品加进购物车两次 |

剩余风险：

- 注入检测是启发式的，收紧规则减少了误报，也可能放过措辞不典型的攻击。它只负责提高警惕；真正的防线仍然是不可信数据包裹、网址和操作的确认。
- 模型仍然可能为了回答问题去操作页面。提示词里已明确禁止（不要为了看总价去加购物车），评测里这类行为已消失，但不能保证所有模型都遵守；付款和下单始终要用户确认。

## 剩余风险

- 安装时的权限提示仍然较重（`debugger`、`tabs`）。`debugger` 不能做成可选权限，是否提供不带它的商店版本尚未决定。
