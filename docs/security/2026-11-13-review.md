## 发现和处理

| # | 严重度 | 问题 | 处理 |
| --- | --- | --- | --- |
| R1 | 中 | 没有授权的网站上，`press` 仍能通过调试接口按键。读不到焦点元素时错误被吞掉，没有目标的回车算 L1，而调试接口的输入不受 Chrome 网站权限限制。复现：正式构建、授权列表为空、自动模式，回车提交了按钮写着「Delete account」的表单，没有任何确认 | 浏览器控制层在每次读页面、注入脚本、发送输入、截图之前都检查：不是浏览器内部页面、没有被屏蔽、已有网站权限，否则拒绝（`src/agent/browser-controller.ts` 的 `assertAllowed`）。`press`、`scroll` 和所有元素操作先走和读页面一样的权限检查，需要时请求授权；同一次任务里被拒绝的网站不再重复询问。读不到焦点元素时不按键 |

## 新增功能带来的检查点

- **导入备份**：文件用 zod 校验。连接的地址和现有的不一致时，不保留已存的 Key，防止伪造的备份文件把 Key 引到别的服务器。
- **导出**：默认不含 API Key，需要手动打开。（之后改为加密导出，见下文「之后新增：加密导出」。）
- **确认卡片的键盘操作**：Esc 拒绝；回车允许一次，高风险步骤要 ⌘/Ctrl + 回车。正在输入文字、或焦点在按钮上时不响应。卡片出现后的 0.5 秒内仍然不接受允许。
- **右键菜单**：新增 `contextMenus` 权限（没有安装提示）。选中的文字和页面内容和从侧边栏附带时一样，按不可信数据处理。
- **更新检查**：只读取版本号和本项目的发布页地址，其他地址一律忽略。

## 之后新增：截图和按坐标点击

评审修复之后加的功能，记在这里是因为它扩大了助手能碰到的范围。

| 方面 | 做法 |
| --- | --- |
| 谁看截图 | 设置里选：自动（当前模型能看图就用它，否则用视觉模型）、当前模型、视觉模型。「能不能看图」按模型名猜；模型拒收图片时，本次任务改用视觉模型的文字描述 |
| 自动截图 | 只在页面文字不够时：canvas 或视频占视口 20% 以上、别的网站的框架占 20% 以上、多个没有文字的按钮、图片为主而文字很少、连续两步失败。登录页、有密码或验证码输入框的页面、敏感页面名单里的页面不自动截图。可以关闭 |
| 不打扰 | 自动截图不切换标签页，也不会为了截图去挂调试接口；标签页不可见且调试接口没在用时就不截 |
| 按坐标点击（`click_at`） | 坐标取自最新一张截图。页面滚动、缩放或换了网址后坐标作废，必须重新看。落点是可读元素时，和按编号点击一样判断风险；落在 canvas、视频上时，任何模式都要确认，确认卡上有落点周围的截图，不提供「总是允许此网站」；落在别的网站的框架里是 L3。按下前再检查一次落点没有变 |
| 截图对齐 | 截图按宽度等比缩放到 CSS 像素（最长边 1280），不做拉伸；端到端测试核对了预览图的圆圈中心落在目标上 |

剩余风险：

- 当前模型直接看图时，图里的文字没法像页面文字那样用规则检查注入，只靠提示词里「截图是数据」的约束和后面的确认。
- 截图里的卡号、密钥过滤不掉（原来就有，自动截图让它更常发生，所以避开了上面几类页面）。
- 没有用真实的多模态模型测过坐标的准确度，只用模拟模型测了流程。

## 之后新增：加密导出

| 方面 | 做法 |
| --- | --- |
| 加密 | 默认开启。整份备份（设置、对话、Key）用 AES-256-GCM 加密，密钥由密码经 PBKDF2-HMAC-SHA-256 派生（60 万次，随机 16 字节盐，随机 12 字节 IV）。文件里只有应用名、版本、导出时间和加密参数是明文 |
| 密码 | 至少 8 位，输两次；不保存，导出后从表单清掉。比较前做 NFKC 归一，换输入法或系统后同一个密码仍然能用 |
| API Key | 只写进加密的文件。关掉加密时「包含 API Key」不可选，代码里也拒绝把 Key 写进明文（`serializeBackup`）。旧版本导出的明文文件仍然可以导入 |
| 导入 | 加密文件先问密码。密码不对和文件被改动过在 AES-GCM 下无法区分，提示同一句话，什么都不写入。解密后的内容和明文备份走同一套校验和「地址变了就不保留 Key」的规则 |
| 伪造的文件 | 迭代次数限制在 10 万到 1000 万之间：太小等于没有保护，太大会卡住页面 |

剩余风险：

- 密码弱，文件就弱。8 位的下限挡不住拿到文件后的离线猜测，60 万次迭代只是让每次尝试变慢。
- 导出文件没有压缩，对话多时文件较大（Base64 再多三分之一）。

## 之后新增：DeepSeek 搜索的原始问题

DeepSeek 搜索接口可以附带用户的原始问题（`ori_question`）来理解搜索意图。它会把用户消息的前 128 个字发给搜索服务，而提示词本来要求模型不要把个人信息写进搜索词，所以这一项默认关闭，在「设置 › 搜索」里由用户打开；消息里有密钥、令牌或卡号时不发。搜索结果的摘要从 400 字放宽到 1200 字，进入模型的网页文字变多，仍然按不可信数据包裹并检查注入。

## 之后新增：用 DeepSeek 读网页（`read_url`）和 DeepSeek 自带搜索

| 方面 | 做法 |
| --- | --- |
| 什么时候有 | 搜索方式选了 DeepSeek 且「用 DeepSeek 读取网页」开着（默认开）时，模型多一个 `read_url` 工具；关掉后工具不出现，运行时也拒绝 |
| 读到的是什么 | DeepSeek 在它的服务器上抓取，看到的是任何人都能看到的内容，不带用户的登录状态。返回的 Markdown 和页面文字一样按不可信数据包裹并检查注入，最多 4 万字 |
| 网址出去之前 | 和打开网址走同一套检查：被屏蔽的网站拒绝；网址里带数据（邮箱、卡号、长编码）要确认；出现过注入后去新网站要确认；任务里没出现过的网站要确认。另外，带用户名密码、密钥或令牌的网址，以及本机地址，一律不发 |
| 失败 | 404、403 时告诉模型改用标签页打开，不重试 |
| 自带搜索 | 「模型自带搜索」现在支持 DeepSeek：向 `/chat/completions` 声明 `deepseek_web_search`，固定用 `deepseek-flash`、关闭思考（开着思考会变成多步的深度搜索）。回答和来源整体按不可信数据处理，来源里的网址不算「已知网站」 |

剩余风险：

- `read_url` 让网址多经过一个第三方。上面的检查挡的是把数据夹在网址里带出去，挡不住 DeepSeek 一侧对网址的记录。
- 读公开网页不再需要逐站授权（原来要开标签页，需要该网站的访问权限）。被屏蔽的网站仍然不读。

## 之后新增：盯页面、框选提问、回放、存为指令、多页调研

这一批功能里，「盯页面」让助手第一次在用户不看的时候自己运行，其余几个新增了存储和发给模型的内容。

| 功能 | 边界 |
| --- | --- |
| 盯页面（`watch_page`） | **只读**：在后台标签页里打开页面读取文字，不点击、不输入、不滚动。没有该网站权限时，开着 DeepSeek 读网页的话走 Fetch 接口，否则检查失败。**创建要确认**：任何模式下都弹确认卡，写明条件，间隔由用户在卡上选（默认 5 分钟，1 秒到 1 天），只有「允许一次」和「拒绝」。网址还要先过和「打开网址」相同的检查。**少问模型**：第一次判断时让模型指出答案依据的页面原文，扩展在页面里定位到对应元素；之后只比对这些元素的文字，没变就不问模型，变了、找不到了、或距上次判断超过 30 分钟（慢的间隔按 10 倍间隔，最多 6 小时）才重新问。模型没指出可定位的文字时，比对整页文字的摘要。**短间隔**：间隔短于 1 分钟的，页面留在一个收起的标签组里，由注入页面的只读脚本监听 DOM 变化并按间隔比对，有变化才通知后台；后台只认这一项自己的标签页发来的消息，并且自己重新读页面，不采信消息里的内容。页面最快每 30 秒重新加载一次（Chrome 定时器的下限，也避免被网站当成机器人）。用户关掉这个标签页即暂停。**急速**：用户可以在列表里对某一项开启 10 分钟的急速，期间每 5 秒重新加载一次，开启前提示可能触发验证码；只有用户能开，模型不能。到时间自动恢复。**放慢**：页面出现验证码或加载失败时，这一次不读也不问模型，急速立即结束，下一次检查推迟 5 分钟（再失败则 10 分钟），并通知用户；用户点「立即检查」不受推迟限制。**有限度**：最多 20 项，30 天后自动结束，连续 3 次检查失败就停并通知。**通知**：文字是固定措辞加上用户确认过的条件，页面和模型写的内容不进系统通知；点通知只打开这一项自己的网址 |
| 框选提问 | 用户自己拖框选区域。选框在页面里的封闭 shadow root 中，截图前已移除。截图优先用 Chrome 的可见标签页截图；没有全部网站权限时，改用右键菜单（点击即获得该标签页的临时权限）或调试接口截一张后立即断开。图片随消息存储，只在当次请求发给模型，之后的轮次只告诉模型「这里有过一张图」 |
| 回放 | 每个会操作页面的步骤开始前存一张 640 像素宽的截图，结束时再存一张；只在不需要额外打扰时截（标签页正在显示，或调试接口已经在用）。登录页、有密码或验证码输入框的页面、敏感页面名单里的页面不截。截图单独存表，随对话删除而清除，可在「设置 › Agent」里关闭 |
| 存为指令 | 存的是用户的原始请求和上次成功步骤的提纲（工具名加目标文字）。输入的内容里像密钥或卡号的不存。重跑时提纲按不可信数据包裹后交给模型，只当提示用，每一步仍然重新判断风险、该确认的照样确认。**不会自己定时运行**：只有用户输入名字才跑 |
| 多页调研（`research_pages`） | 一次最多 12 个网址。只读任务里已经出现过的网站；没出现过的、网址里带数据的、被屏蔽的一律跳过并告诉模型原因，不在批量里弹确认。每页交给快速模型摘出和问题有关的内容，结果按不可信数据包裹 |
| 表格导出 | CSV 里以 `=`、`+`、`-`、`@` 开头且不是纯数字的单元格前面加单引号，防止表格软件把它当公式执行 |
| 朗读 | 用浏览器的语音合成，文字不发往任何地方 |

剩余风险：

- 页面里的注入文字可能让快速模型误判成「满足」，或者让它指出一段不会变化的文字、从而漏掉真正的变化；前者的后果是一条误报的通知，后者靠定期重新判断兜底。都不会触发任何操作。
- 间隔是「最快」而不是保证：Chrome 会给后台标签页的定时器降频（先是每秒一次，隐藏几分钟后可降到每分钟一次），页面自己靠定时器刷新的内容也一样被降频。不会自己更新的页面只能靠重新加载发现变化，平时最快 30 秒，急速时 5 秒。
- 短间隔的盯页面会让一个标签页长期开着并每 30 秒重新加载，对网站来说是持续的访问。急速期间访问更密，网站可能弹验证码、限流或标记账号；验证码检测靠常见的几种特征，认不出的拦截页会被当成普通页面交给模型判断。
- 急速期间后台靠连续的调用保持运行；Chrome 若中途回收后台，最迟 30 秒后由定时器接上，期间会少刷几次。
- 慢间隔的检查，后台标签页会在标签栏里闪现几秒。
- 盯着的页面不包含在导出文件里：导入一个文件不应该悄悄带来后台任务。
- 回放截图里可能有页面上的个人信息。它们只存在本机，随对话一起删除，也会进入加密或明文的导出文件。
- 存为指令之后「定时自动重跑」没有做，是否要做尚未决定：那会让助手在没人看的时候操作网站，需要先定好边界。

## 之后新增：提示词缓存、购物、注入检测收紧

| 方面 | 做法 |
| --- | --- |
| 提示词缓存 | 不改变发给模型的内容，只是让每次调用的开头（指令、工具、此前的对话）逐字节重复，供应商因此少收费。Anthropic 需要在请求里标出缓存位置，标在指令末尾和「最新一次页面视图之前」；OpenAI 额外带上对话 id 作为缓存路由键；其他供应商自动缓存。为了让历史消息每次渲染一致，用户消息会记下发送时所在标签页的标题和网址 |
| 商品元数据 | 页面的 schema.org 商品数据（名称、价格、库存、卖家、评分）放在页面文字前面。它是页面里人看不到的内容，所以只取有类型的字段、限制长度、价格必须是数字，并且和页面文字一起按不可信数据包裹和检查 |
| 商品页识别 | 侧边栏打开且有该网站权限时，注入一小段只读脚本判断页面是否声明了商品数据，只返回是或否，用来决定显示哪组快捷入口 |
| 注入检测 | 规则从「提到 AI 相关词」收紧为「像是在对 AI 下指令」：要有对象、要丢弃的东西或要发往的地方。25 个普通网页（接口文档、百科、新闻、商店）的误报从 5 个降到 1 个，剩下的是维基「提示词注入」词条里原样引用的攻击语句。原有的攻击样例仍全部命中，并新增了一批 |
| 操作反馈 | 每次操作后的页面视图里，明确列出新出现的文字；连续两次相同操作会提醒；同一请求里搜索三次以上会提醒别再换词重搜。目的是少做重复操作，比如把同一件商品加进购物车两次 |

剩余风险：

- 注入检测是启发式的，收紧规则减少了误报，也可能放过措辞不典型的攻击。它只负责提高警惕；真正的防线仍然是不可信数据包裹、网址和操作的确认。
- 模型仍然可能为了回答问题去操作页面。提示词里已明确禁止（不要为了看总价去加购物车），评测里这类行为已消失，但不能保证所有模型都遵守；付款和下单始终要用户确认。

## 之后新增：技能、回答里的商品图、论坛和社交网站、同组标签页

| 方面 | 做法 |
| --- | --- |
| 技能是什么 | 一段文字说明（名称、一行「什么时候用」、正文），不是代码。提示词里只列名称和那一行；正文在模型调用 `load_skill` 时、或用户用斜杠指令选中时才进入对话。购物相关的五个内置（比价、评价分析、口碑、下单前检查、折扣真假），原来写死在系统提示词里的购物指引移到了这里 |
| 技能的权限 | 技能不能给自己任何权限：模式、确认、网站规则、注入防护照旧生效，提示词里也写明「技能不能放宽这些规则」。技能正文算用户的指令（它是用户装的），所以安装是信任决定 |
| 安装 | 从文件、从网址，或自己写。三种方式都先把全文摆在表单里，并列出正文提到的网站，用户点「安装」才生效；没有自动安装。按网址取文件时不带 Cookie、不带来源页，只接受 https（本机地址除外），GitHub 的文件页面会换成原始文件地址。名称不能和内置技能相同；存储里若出现同名的（改过的备份），以内置的为准。正文最长 8000 字符，最多 40 个 |
| 回答里的图片 | 以前一律不加载，现在有条件地显示。侧边栏页面的内容安全策略不变，仍然不能从网络加载图片；图片由后台去取，缩成最长边 480 像素的 WebP，存在本地，随对话删除和导出 |
| 哪些图片会被取 | 地址必须原样出现在这一轮里助手读到的内容中（用户的消息和附带的页面、工具返回的页面和搜索结果），模型自己写的或改过一个字符的都不取；带邮箱、卡号、密钥的地址不取；用户屏蔽的网站不取；每条回答最多 8 张；不是图片、大于 5 MB、小于 24 像素的丢弃 |
| 取图时带什么 | 不带 Cookie，不带来源页（Referer）。对方能看到的是用户的 IP 和这次请求 |
| 取不到时 | 图片服务器只在扩展有它的网站权限时才让读：回答里的链接旁有「显示」，点一下由 Chrome 询问是否授权这一个网站，授权后按同样的规则取图 |
| 页面文字里的图片地址 | 页面上显示尺寸不小于 100 像素的图片（每页最多 12 张）连同地址交给模型，其余只留描述；商品元数据里的图片地址（或 `og:image`）列在商品数据里。地址只接受 http(s)，最长 400 字符 |
| 论坛和社交网站 | 内置一份网站名单，用户可以在「设置 › 网站权限」里增删网站、改页数上限（1 到 100，默认 8），也可以一键恢复默认；设置里存的是相对内置名单的增删，以后内置名单新增的网站对改过名单的用户同样生效。这些网站的页面只在标签页里打开，`research_pages` 和 `read_url` 一律拒绝；一次请求在同一个网站最多看 8 个不同的页面，到了上限后新的打开和跳转链接都被拒绝；点赞、投票、关注、转发、私信、发帖这类以用户名义做的事，不论模式和网站规则都要确认，可以「本次任务允许」，不提供「此网站一直允许」 |
| 同组标签页 | 用户在助手的标签组里新开的标签页、或拖进这个组的标签页，会显示这个组的对话。只认标题是助手组名的标签组；用户自己的标签组不受影响 |

剩余风险：

- 安装的技能就是指令。恶意技能可以让助手去读某些页面、在回答里写某些话；它不能绕过确认，但用户确认时看到的是单步操作，不一定能看出整体意图。靠安装前阅读来防。
- 图片：页面能决定「助手读到的地址里哪一个被取」，这最多泄露几个比特（比如页面给出很多地址，让模型按某个条件选一个）。每条回答 8 张的上限限制了这个通道，但没有消除。图片服务器能知道用户的 IP 和取图时间。
- 取图走扩展的权限：没有那个图片服务器的网站权限、对方又不允许跨域读取时取不到。这时后台记下一个「待显示」的占位（只记它自己按上面的规则判定可取的地址），回答里显示成链接加一个「显示」按钮；用户点击时侧边栏向 Chrome 申请这一个网站的权限，同意后后台按同样的规则去取，同一对话里这个网站的其他待显示图片一并取回。侧边栏页面仍然不从网络加载图片。代价是：用户授权后，扩展对这个图片网站也有了读取和操作权限（Chrome 的权限不分用途），助手之后也能在这个网站上工作，除非用户在网站权限里撤销或屏蔽它。伪造的显示请求只能触发已记为待显示的地址。Chrome 的权限弹窗本身没有被自动化测试覆盖（测试版本默认已授权所有网站）。
- 社交网站的识别靠名单和按钮文字，名单之外的论坛按普通网站对待（用户可以自己加）；用户把网站从名单里删掉、或把页数调得很大，这些保护也就相应没有了；图标按钮没有文字或无障碍名称时认不出是点赞。
- 助手用用户的登录状态浏览这些网站，网站可能把它当成自动化访问。页数上限和「只在标签页里打开」降低了访问量，不能保证不触发风控。

## 之后改动：技能改用 Agent Skills 标准格式

| 方面 | 做法 |
| --- | --- |
| 格式 | 按 [Agent Skills 规范](https://agentskills.io/specification)：一个技能是一个文件夹，文件夹名就是技能名，里面有 `SKILL.md`（YAML 头部加 Markdown 正文）。头部的 `name`、`description` 必填，`license`、`compatibility`、`metadata`、`allowed-tools` 可选；头部用 YAML 库解析，别名展开有上限。内置的五个技能各在 `src/skills/builtin/<名称>/SKILL.md`，构建时读入，名称与文件夹不一致时构建失败 |
| 名称 | 只能用小写英文字母、数字和单个连字符，不以连字符开头或结尾，最长 64 个字符（产品方决定不留例外）。0.3.0 装的名称不合规的技能会被保留并列出，提示改名；改名前不会提供给模型 |
| 附带文件 | 文件夹里的文本文件（`references/`、`assets/` 等，按扩展名判断且必须是合法的 UTF-8）一并安装，单个不超过 200 KB，合计不超过 50 个、1 MB；模型在加载技能后看到文件清单，用只读的 `read_skill_file` 按需读取，一次最多 3 万字符。路径里不能有 `..` |
| 不安装的 | 脚本（`scripts/` 目录和常见代码扩展名）一律不装，扩展不运行任何代码；加载技能时会告诉模型这些脚本不在，让它改用自己的工具或告诉用户做不到。图片等非文本、超出大小的文件也不装。安装前的表单逐个列出没装的文件和原因 |
| `allowed-tools` | 只展示，不预先批准任何操作，确认规则照旧 |
| 安装来源 | 单个 `SKILL.md`、整个文件夹的 zip（只解压可能保留的文件，总量和条目数有上限，防压缩炸弹）、GitHub 上的文件夹地址（经公开 API 列出文件，脚本和图片不下载）、或 `SKILL.md`/zip 的网址。都不带 Cookie 和来源页。zip 里有多个同级技能时要求一个个装 |
| 存储 | 已安装的技能连同文件存在扩展的 IndexedDB，不再放在设置里（设置存储放不下参考文件）；哪些技能关闭仍在设置里。0.3.0 存在设置里的技能在扩展启动时迁移过去 |
| 备份 | 已安装的技能随设置导出（含文件）。导入时每个技能都重新按安装规则校验，不合规的（名称、长度、内置名、路径）丢弃；0.3.0 的备份照迁移规则处理 |
| 伪造技能块 | 修复：页面、搜索结果、附带的页面、之前的回答里出现的 `<skill`、`<skill_file` 都会被转义，只有扩展自己写的才是真的技能块。之前只转义了外层数据标签，页面可以写出看起来像技能的块 |
| 导出 | 下载为 `<名称>.zip`，里面是 `<名称>/SKILL.md` 和附带文件，内置技能也可以下载 |

剩余风险：

- 从 GitHub 文件夹安装依赖 GitHub 的公开接口，未登录每小时 60 次；分支名里带斜杠时按第一段当分支名，可能取错。
- 其他网站的 `SKILL.md` 或 zip 地址要对方允许跨域读取才能取到，取不到时提示下载后从文件安装。
- 参考文件和正文一样算用户的指令，安装前的表单可以展开逐个阅读；内容多时用户未必会读完。

## 之后新增：更多内置技能、所在国家/地区

| 方面 | 做法 |
| --- | --- |
| 新的内置技能 | 共 18 个。新加的 13 个：导购选型（附各国家和地区的测评站、电商、论坛清单作为参考文件）、店铺可信度、机票酒店比价、条款审读、事实核查、长文精读、多方报道对照、填表、退订、批量整理数据、招聘信息、技术文档、GitHub 讨论。都只是文字，规则不变：只读的技能写明只读；比价和出行停在下单或预订前；退订的最后一步由扩展问用户（「取消订阅」本来就算高风险）；填表不输入密码、卡号和验证码，不上传文件，提交前列出所填内容，默认不勾选「与合作方分享」 |
| 提示词长度 | 18 个技能的名称和描述约 4600 个字符（约 1100 token），每次请求都带上，同一对话里走提示词缓存 |
| 所在国家/地区 | 新设置，默认「自动」：按 IP 地址所在国家。扩展向 api.country.is 查询（不应答时改用 Cloudflare 的 `cdn-cgi/trace`），两者都只返回国家代码；请求不带 Cookie 和来源页，结果缓存 12 小时，查询失败时最多沿用 7 天内的旧结果，再失败就不告诉模型。不按浏览器语言推断（语言说明不了人在哪儿）。也可以指定国家，或选「不告诉模型」，这两种情况都不查询。系统提示词里多一行：用户在哪个国家，按 IP 判断时提醒模型 VPN 和出行会让它不准，关键时说明假定的国家。这个信息随每次请求发给模型服务商；查询服务会看到用户的 IP 地址。测试版本不做查询 |
| 论坛名单 | 导购参考文件里提到的论坛（Mobile01、PTT、LIHKG、5ch、뽐뿌、클리앙、RedFlagDeals、hotukdeals、mydealz、Dealabs、Chollometro、OzBargain）加入了论坛和社交网站名单，同样只在标签页里看、有页数上限、互动先问 |
| 斜杠菜单 | 没有专属快捷指令的技能（内置和安装的）都出现在斜杠菜单里；商品页的快捷入口多了「这家店靠谱吗」 |

剩余风险：

- 技能越多，模型选错技能的机会越多。评测里每个技能有一题检查会不会被加载、一题检查无关问题不加载，但真实请求更杂。
- 参考文件里的网站清单是写死的，网站会关停或改版；技能正文要求核实网站仍在且评测是新的。
- 退订、填表会在真实网站上操作，只在本地编造的页面上验证过。

## 之后改动：什么算「用户接管了页面」

助手在页面上工作时，用户自己操作页面会让任务暂停，避免两边同时操作。之前页面上任何一次真实的鼠标按下或按键都算，于是切回窗口时点一下、按一下 Shift 或 Cmd、复制、打开侧边栏的快捷键、右键、选中文字都会暂停。现在只有这些才算：

- 鼠标左键按在可操作的元素上（链接、按钮、输入框等）；
- 在输入框里打字；
- 焦点在按钮或链接上时按 Enter 或空格。

不算的：单独按修饰键、带 Ctrl/Cmd/Alt 的快捷键、功能键、只用来滚动的按键、鼠标中键和右键、点在文字或空白处。

剩余风险：点空白处有时会关掉页面上的弹层，这类变化不再暂停；助手每次操作前都会重新读页面，元素没了会报错重看，不会点错地方。

## 之后改动：步数上限和防绕圈

- 每个任务的步数上限默认从 30 提到 100，设置里可填 5 到 500。之前存的 30 视为没改过默认值，升为 100；其他数值保留。
- 上限提高后，绕圈的代价也变大，所以加了两道硬性拦截：同一地址在一次请求里打开满 4 次后不再打开；同一操作（工具、参数、标签页都相同）失败 2 次后不再执行，并告诉模型换个做法或向用户说明。原有的保护仍在：连续 6 次失败终止任务、同一页面来第三次起提醒、紧接着重复点击「加入购物车」这类按钮会被拦一次、搜索三次以上提醒。
- 没有拦截的：成功的操作在不同页面之间的重复（比如把一个多步流程重走一遍）。高风险步骤每次都要用户确认，用户会在第二次确认时看到；技能里也写明流程只走一遍。

## 之后新增：分阶段输出、工作中补充

- **分阶段输出**：新工具 `report_progress`，只读，不碰页面。模型用它把一个阶段的结果（Markdown）作为回答的下一部分立刻显示出来；最终回答接在后面。这些部分和任务一起保存，任务被停止或失败时也保留在回答里，对话删除或重新生成时一并清除。每次最多 12 部分、合计 4 万字符。其中的图片照原规则取（只取助手读到过的地址）。七个多步骤的内置技能改写成了阶段。
- **工作中补充**：助手工作时，输入框里打的字会作为对当前任务的补充发给它，在下一步之前读到；如果它正写到最终回答，这次回答作废，带着补充重来。补充的话存在对话里，算用户的指令；其中提到的网站视为用户指定的网站。只发文字，不带附件。
- 没有改变的：确认、模式、网站规则照旧；`report_progress` 的内容是模型写的，进入后续对话时同样会转义技能标签。
