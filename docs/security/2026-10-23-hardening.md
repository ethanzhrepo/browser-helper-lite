## 2. 独立审查的发现与处理

行号对应被审计版本 `b22c5df`。

### N1 · 中 · 批准没有和具体的操作绑定

- **位置**：`src/agent/types.ts:108`、`src/agent/runtime.ts:251-260`、`entrypoints/sidepanel/AgentRunView.tsx:230-234`。
- **问题**：侧边栏发回的批准只有 `{kind: 'approval', decision}`，后台把它交给当时正在等待的那一个审批。
- **利用场景**：模型一步里发了几个操作。你批准了卡片 A，卡片 B 紧接着出现在同一位置。双击的第二下，或者晚到的一条消息，会把你没看过的 B 也批准掉。
- **核实**：已确认。
- **修复**：
  - 批准里带上 `actionId`，后台只接受和当前等待的操作一致的批准（`respond()`）。
  - 卡片出现后的 0.5 秒内，「允许」类按钮不可点；「拒绝」随时可点（`APPROVAL_ARM_MS`）。
  - 每张卡片按 `actionId` 重新挂载，计时重新开始。

### N2 · 中 · 批准之前检查过的东西，批准之后不再检查（①也发现）

- **位置**：`src/agent/runtime.ts:758-768, 776-811, 814-879`。
- **问题**：风险判断用的是等待之前描述的目标，批准后直接执行。等待可能持续好几分钟。在这段时间里：
  - 页面可以把按钮文字换掉，比如「保存」变成「删除账户」；
  - 页面可以把焦点移走（`press` 作用在当时获得焦点的元素上）；
  - 页面可以跳转；
  - 框架可以把同一个 DOM 节点复用给列表里的另一行。
- **利用场景**：在账户页面上，卡片写的是「保存」。你点「允许一次」时，同一个位置已经是「删除账户」。
- **核实**：已确认。
- **修复**（`guarded()`）：
  - 批准后、执行前，重新描述目标（`describeTarget` 或 `describeFocused`），并重新读取标签页和网址（忽略 `#` 后面的部分）。
  - 比较这些内容（`sameTarget`）：标签和文字、链接、所属表单的提交按钮、是否在别的网站的框架里、是否下载、下拉选项。输入框的值不比较，那是你可以改的。
  - 有任何变化就不执行，告诉模型「页面在你确认时变了」，并给它最新的页面视图。它重新操作时会重新判断风险，必要时再问你。
  - 这个检查放在记住「本任务内都允许」「总是允许此站点」之前，所以作废的批准不会留下任何授权。
- **测试**：E2E `tests/e2e/hardening.spec.ts` 第 1 个用例：卡片出现后，测试把「Save」改成「Delete account」，然后点「允许一次」。断言页面上的保存次数仍是 0，随后出现针对「Delete account」的高风险确认。单元测试 `tests/unit/hardening.test.ts`（`sameTarget`）。

### N3 · 中 · 别的网站嵌入的框架是风险判断的盲区

- **位置**：`page-agent.ts:237-252, 419-426, 535-551`、`risk.ts:99-110`。
- **问题**：
  - 焦点在跨站 iframe 里时，`deepActiveElement()` 停在 `<iframe>` 上。这时按回车被当成作用在一个空元素上，只算 L1。
  - 点击前的遮挡检查把落在目标内部的 iframe 当成「没有遮挡」。外层元素的文字很普通，真实的点击却落在扩展读不到的内容上。
- **利用场景**：自动模式下，在嵌入的支付或授权小组件里点「确认」，绕过「L3 必须确认」。
- **核实**：已确认。
- **修复**：
  - 页面脚本计算目标中心点会落进哪个读不到的框架（`frameAtCenter`），记在 `TargetInfo.frameOrigin` 里，标签上注明「（在来自 … 的框架里）」。
  - 在这种目标上点击、输入、按回车或字符键，一律按 L3（原因 `frame`）处理，逐次确认，卡片上显示框架来自哪个网站。
  - 点击前的命中检查中，如果指针下是另一个读不到的框架，按「被遮挡」取消。
- **测试**：单元测试 `agent-rules.test.ts`（框架内的点击和按键）。

### N4 · 中 · 自动模式下粘贴剪贴板不需要确认（H3 的修复不完整）

- **位置**：`risk.ts:101-102`、`drivers/cdp.ts:128-142`。
- **问题**：第一轮把组合键定为 L2，而自动模式会自动执行 L2。通过 CDP 按 `Ctrl+V`，会在 Windows 和 Linux 上把系统剪贴板粘贴到页面里。剪贴板里可能有你刚复制的密码或验证码，模型从没见过这些内容。
- **核实**：代码路径已确认；各操作系统上的实际效果没有逐一验证。
- **修复**：`Ctrl/Cmd+V`（包括 `Ctrl+Shift+V`）和 `Shift+Insert` 按 L3（原因 `clipboard`）处理，卡片上写明「会粘贴你剪贴板里的内容」。
- **测试**：单元测试 `agent-rules.test.ts`。

### N5 · 中 · 网址里的数据检查漏了几个位置（H2 的修复不完整）

- **位置**：`injection.ts:123-145`。
- **问题**：只检查了参数值、`#` 后的部分、路径和用户名。没检查：参数名（`?x@y.com` 时值是空的）、密码字段、子域名，以及拆成很多个短参数的情况。
- **核实**：已确认（`?x@y.com` 确实能绕过）。
- **修复**（`urlDataLeak`）：
  - 另外检查参数名、整段查询（把拆开的值连起来看）和密码字段。
  - 查询总长不少于 600 个字符算数据。
  - 有不少于 40 个字符、字母和数字混合的子域名标签也算数据：数据藏在子域名里时，打开网址之前的 DNS 查询就已经把它送出去了。
  - 同时加上密钥、令牌的识别（见 D2）。
- **测试**：单元测试 `injection.test.ts`。

### N6 · 中 · 页面和模型输出可以扩大「已知网站」的范围

- **位置**：`runtime.ts:348-352, 397-400, 628, 961, 972, 999`。
- **问题**：
  - 标签页最终停在哪个网站，那个网站就算「已知」，包括页面自己跳转过去的。
  - 模型自带联网搜索的回答里出现的网址也算已知。这段回答是由读过网页的模型写的。
  - 你请求里任何 3 个字母以上的词，加上任意顶级域名都算已知，比如请求里有 shoes，`shoes.xyz` 就算已知。
  - 发现注入后，发起注入的网站仍在「可信」名单里。
- **核实**：已确认。
- **修复**：
  - 「已知」只包括：当前标签页，你请求里写出的域名，你 `@` 进来的标签页，助手点过的链接（按链接本身，不按跳转后落在哪里），API 搜索结果，以及你批准过的网站。
  - 不再把「标签页停在哪个网站」和联网搜索回答里的网址算进去。
  - 请求里的词只在常见顶级域名下有效（`.com`、`.cn`、`.co.uk`、`.de`、`.jp` 等，见 `COMMON_SUFFIXES`）。
  - 发现注入后，发起注入的网站移出可信名单，即使它是你自己的标签页。
- **代价**：用模型自带的联网搜索时，去结果里的网站需要确认一次（可以选「本任务内都允许」）。

### N7 · 低 · 模型能看到它不需要的输入框内容（①也发现）

- **位置**：`page-agent.ts:195-208`。
- **问题**：页面快照只隐藏了密码框的值。自动填好的银行卡号、有效期、安全码和验证码输入框的值都会发给模型供应商。
- **修复**：这些字段（`autocomplete="cc-*"`、名称里有 card number/cvv/cvc、`one-time-code`）的值显示成 `••••`，和密码框一样。另见 D1：所有发给模型的内容都会再过滤一遍卡号和密钥。
- **测试**：E2E `hardening.spec.ts` 第 2 个用例（预填的卡号和安全码都没有出现在发给模型的内容里）。

### N8 · 低 · 拆开输入可以绕过卡号、密码框的禁止

- **问题**：
  - `press` 一次按一个字符，不检查焦点所在的字段。
  - `type` 用 `clear: false` 分几次追加，每次只检查新输入的那一段，拼起来就是一个完整的卡号。
- **修复**：
  - 在密码、银行卡、验证码字段上按字符键，和 `type` 一样禁止。
  - 按字符键时检查「已有内容 + 这个字符」是否构成卡号。
  - `type` 追加时检查追加后的完整内容。
- **测试**：单元测试 `agent-rules.test.ts`。

### N9 · 低 · `select_option` 总是 L1

- **问题**：不检查选中项的文字；页面可以把选项的值设成 `keep`、文字写成「删除我的账户」。
- **修复**：
  - 页面脚本把下拉框的选项（最多 200 个）放进 `TargetInfo.options`。
  - 风险判断和页面脚本共用同一个匹配函数（`src/agent/select.ts` 的 `matchOption`），按真正会被选中的那一项的文字判断风险。
- **测试**：单元测试 `agent-rules.test.ts`。

### N10 · 低 · API Key 可以走明文 HTTP（①也发现）

- **问题**：任何厂商的 `baseURL` 都接受 `http:`，输错或被改成 `http://` 时，Key 就明文发了出去。
- **修复**：
  - 新增 `keyedBaseURL`（`src/providers/vendors.ts`）：带 Key 的请求只能走 https，或者走发往本机的 http（`localhost`、`127.0.0.0/8`、`::1`）。
  - 对话、联网搜索、语音识别、模型列表、搜索 API 都经过这个检查，否则报新的错误类型 `insecure`。
  - 设置页保存连接时也会提示。局域网里不带 Key 的服务（比如另一台电脑上的 Ollama）不受影响。
- **测试**：单元测试 `hardening.test.ts`。

### N11 · 低 · CSP 没有限制字体和框架（审查人未验证）

- **修复**：扩展页面的 CSP 加上 `font-src 'self' data:`、`media-src 'self' blob:`、`frame-src 'none'`、`base-uri 'none'`、`form-action 'none'`。构建产物里 KaTeX 字体都是扩展内的相对地址，不受影响。

### 关于收窄权限的建议

审查建议把 `tabGroups`、`notifications`、`debugger` 改成用到时再申请。处理见 §5。

## 3. 开发会话自己的加固项

| # | 加固 | 做法 |
| --- | --- | --- |
| D1 | **卡号和密钥根本不给模型看**：模型看不到的东西，也就不会被骗着发出去 | `redactSensitive` 把以下内容替换成 `[card number hidden]` 或 `[key or token hidden]`：卡号（卡组织号段 + Luhn 校验 + 常见分组写法）、常见格式的密钥和令牌（`sk-…`、`sk_live_…`、`ghp_…`、`github_pat_…`、`glpat-…`、`AKIA…`、`AIza…`、`xox?-…`、`hf_…`、JWT、私钥块）。作用范围是所有发给模型的网页内容：页面快照、`read_page`、搜索结果、提取结果、截图描述、`@` 附带的页面，以及标签页标题和网址 |
| D2 | **密钥不往外发** | 要输入的文字像密钥时，按 L3（原因 `secret`）逐次确认；网址里有密钥时按「带数据」处理；搜索词里有密钥或卡号时直接拒绝，不发给任何搜索服务 |
| D3 | **敏感页面每一步都确认** | `src/agent/sensitive.ts`。在下列页面上，任何改动都要你确认，不管什么模式、网站策略是什么，而且只能逐次批准；浏览不受影响：<br>· 账户和安全页面（Google、Microsoft、Apple 账户等）<br>· 密钥和令牌页面（`/settings/tokens`、`/api-keys` 等）<br>· OAuth 授权页和设备登录页<br>· 代码托管网站的仓库和组织设置<br>· 云控制台（AWS、Azure、GCP、Cloudflare、阿里云、腾讯云等）<br>· 模型厂商的控制台<br>· 密码管理器<br>· 支付服务（PayPal、Stripe 后台、支付宝等） |
| D4 | **更多 L3 按钮文字** | 四种语言补充以下按钮文字：撤销授权或令牌、生成和创建令牌或密钥、转让所有权、设为公开、修改邮箱、重置密码、关闭两步验证、「批准」、「添加至 Chrome」、安装扩展。中文的「撤销」单独出现时是「撤销操作」的意思，所以不算 |
| D5 | **下载按风险处理** | 指向程序的链接或网址（`.exe`、`.dmg`、`.apk`、`.msi`、`.ps1`、`.crx` 等）按 L3 处理。压缩包和带 `download` 属性的链接按 L2 处理。`navigate` 和 `open_tab` 打开程序下载地址时也逐次确认 |
| D6 | **回复里带数据的链接点两次才打开** | 网址里带数据（判断规则同 `urlDataLeak`）时，第一次点击只显示完整网址和提醒，第二次才真正打开（`ReplyLink`）。普通链接不受影响 |
| D7 | **`@` 附带的页面和其他网页内容一样处理** | 以前只转义了结束标签。现在还会转义开始标签、替换对话控制符、过滤卡号和密钥；标题截到 200 个字（`renderContext`） |
| D8 | **发现注入后，权限卡片不再提供「允许所有网站」** | 网站访问权限只能一个网站一个网站地给 |
| D9 | **卡号识别更准** | 加上卡组织号段和分组写法的判断。随机长数字约有 1/10 能通过 Luhn 校验，比如订单号 402-1234567-1234567；以前它们可能被误当成卡号而禁止输入，现在不会 |
| D10 | **审批后页面视图跟上** | 因为「页面变了」被拒绝的操作，也会给模型一份最新的页面视图（N2 的配套） |

## 4. 修复过程中发现的问题

- 第一版 TOCTOU 检查放在保存「总是允许此站点」之后：如果页面在等待时变了，操作虽然没执行，「总是允许」却已经保存了。提交前的自查发现了这个问题，已经把检查移到所有授权记录之前。
- `sameTarget` 一开始没比较下拉选项和框架来源，单元测试发现后补上了。

## 5. 评估后决定不改的

| 建议 | 结论 |
| --- | --- |
| 把 `debugger` 改成用到时再申请 | 做不到：Chrome 不允许把 `debugger` 声明为可选权限（`debugger`、`declarativeNetRequest`、`devtools` 等在例外名单里）。保留构建开关：`pnpm build:no-cdp` 的产物不含这个权限，代价是点击和输入改成模拟事件，有些网站不认 |
| 把 `tabGroups`、`notifications` 改成可选 | 收益很小：这两个权限都读不到网页数据，安装时也不显示警告。改成可选要多处处理「还没授权」的情况，暂不改 |
| 用 CSP 的 `connect-src` 限制能连接的服务器 | 用户可以自定义 OpenAI 兼容服务的地址，CSP 列不出这些地址。改为在代码里限制 Key 只能走 https 或发往本机的 http（N10） |

`tests/e2e/hardening.spec.ts` 的三个用例：

1. **敏感页面和被调包的按钮**（`/settings/security`，自动模式）：
   - 点「Save」也要确认，卡片说明这是账户安全页面，没有「本任务内都允许」和「总是允许此站点」。
   - 卡片出现后，页面把按钮改成「Delete account」，然后点「允许一次」：什么都没点，保存次数还是 0。
   - 模型看到新页面后再点，弹出高风险确认；拒绝。
   - 最终两个操作都是「已拒绝」，页面没有任何变化。
2. **卡号和密钥不给模型**（账单页面上显示着卡号和新生成的 API Key，表单里预填了卡号和安全码）：
   - 发给模型的内容里出现了 `[card number hidden]` 和 `[key or token hidden]`。
   - 发给模型的内容里没有出现任何一个原始卡号、Key 或安全码。
   - 模型试图拿 Key 去搜索时被拒绝，搜索页没有收到请求。
3. **回复里带数据的链接**：
   - 第一次点击只显示完整网址和提醒，没有打开新页面，服务器没有收到 `/collect` 请求。
   - 普通链接照常打开。

## 7. 剩余风险与后续工作

| 风险 | 说明 | 计划 |
| --- | --- | --- |
| 规则识别仍会漏 | 注入识别、按钮文字、敏感页面都是规则。换个说法、没列进去的网站（比如各家网银）都会漏 | M2：用快速模型判断「这个操作是否服务于你的原始请求」。网银、邮箱、公司后台这类网站，建议在设置里设成「只读」或「每步确认」 |
| 截图里的敏感信息 | `look` 把截图发给视觉模型，图片里的卡号和密钥没法过滤 | 处理敏感页面时少用 `look`；以后可以考虑在敏感页面上禁用截图 |
| 数据仍可能通过已知网站带出 | 很短的明文参数、分多次发送、写进已知网站的表单都可能绕过 | 和第一轮一样，靠新网站确认、谨慎模式和你的确认；M2 一并评估 |

| 两份审查都由 AI 完成 | 没有经过人工渗透测试 | 上架前请人工审查一次 |
